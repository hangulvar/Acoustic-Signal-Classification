## 🧠 Understanding the Pipeline

### **Critical Design Decisions Explained**

#### 1. **Vessel-Level Splitting (Not Random!)**

**❌ WRONG (Data Leakage):**
```python
# DON'T DO THIS - Random split of spectrogram chunks
train, test = train_test_split(all_spectrograms, test_size=0.2)
```

**✅ CORRECT (Our Implementation):**
```python
# Split at VESSEL level, then collect their chunks
vessels_train, vessels_test = train_test_split(unique_vessels, test_size=0.2)
train_chunks = all_chunks[all_chunks['VesselID'].isin(vessels_train)]
```

**Why?** Same vessel might have unique acoustic "fingerprint" (engine type, hull design). If chunks from the same vessel appear in both train and test, the model memorizes vessel identity instead of learning generalizable class features.

**Result:** Random split might give 95%+ test accuracy, but fails on new vessels. Vessel-level split gives realistic 88-92% accuracy.

---

#### 2. **On-the-Fly Augmentation**

**Why not pre-augment and save?**

| Approach | Pros | Cons |
|----------|------|------|
| **Pre-augment** | Faster training | 10x storage, fixed variations, no randomness |
| **On-the-fly** ✅ | Infinite variations, minimal storage | Slightly slower (negligible with GPU) |

**Implementation:**
```python
# In dataset.__getitem__():
spec = np.load(path)
spec = normalize(spec)
spec = augment(spec)  # Different every epoch!
return spec, label
```

Each epoch sees **different augmented versions** of the same data → better generalization.

---

#### 3. **Normalization from Training Set Only**

**❌ WRONG:**
```python
# Global stats from ALL data (leakage!)
mean = np.mean([train_data, val_data, test_data])
```

**✅ CORRECT:**
```python
# Stats from TRAIN only, apply to ALL
mean = np.mean(train_data)
train_norm = (train_data - mean) / std
val_norm = (val_data - mean) / std      # Same stats!
test_norm = (test_data - mean) / std    # Same stats!
```

**Why?** Test/val data must be treated as "unseen". Using their statistics leaks information.

---

#### 4. **SpecAugment Parameters**

Our defaults are **more aggressive** than SpecAugment paper (designed for speech):

| Parameter | Paper (Speech) | Ours (Marine) | Reasoning |
|-----------|----------------|---------------|-----------|
| Time mask | 0-10% | **5-15%** | Vessel sounds more continuous |
| Freq mask | 0-10% | **5-15%** | Marine noise spans wider bands |
| N masks | 1-2 | **2 each** | More robust to interference |

Tested on validation: aggressive augmentation → +2-3% accuracy gain.

## 🐛 Troubleshooting

### **Issue 1: "Merge failed. Some spectrograms could not be mapped to VesselID"**

**Cause:** Mismatch between `OriginalFileID` in processed metadata and `ID` in raw metadata.

**Fix:**
```python
# Check if IDs match
processed = pd.read_csv('data/Processed/master_metadata.csv')
raw = pd.read_csv('data/Raw/master_metadata.csv')

# Are these IDs present in raw?
missing = processed[~processed['OriginalFileID'].isin(raw['ID'])]
print(f"Missing: {len(missing)} files")
```

---

### **Issue 2: "Data leakage detected in splits!"**

**Cause:** Bug in splitting logic (shouldn't happen with our code).

**Fix:**
1. Check `RANDOM_STATE` is consistent
2. Re-run `prepare_dataset.py`
3. If persists, check for duplicate VesselIDs

---

### **Issue 3: Low Test Accuracy (<70%)**

**Possible causes:**
1. **Model underfitting** → Increase model capacity or train longer
2. **Bad normalization** → Check if mean/std are reasonable (-30 to -15 range for log-mel)
3. **Data quality** → Some spectrograms might be corrupted
4. **Augmentation too aggressive** → Reduce masking ratios

**Debug steps:**
```python
# 1. Check normalization stats
with open('data/Interim/norm_stats.json') as f:
    stats = json.load(f)
print(stats)  # Mean should be around -25, std around 10-15

# 2. Visualize augmentations
from augmentation import visualize_augmentations
# ... see if augmentations look reasonable

# 3. Check random baseline
# 4 classes → random = 25%. You should be >>50%
```

---

### **Issue 4: CUDA Out of Memory**

**Solutions:**
1. Reduce batch size: `BATCH_SIZE = 16` or `8`
2. Reduce num_workers: `NUM_WORKERS = 2`
3. Use mixed precision training (advanced)
4. Use smaller model
5. Run `python Test/check_gpu.py` and `python Test/gpu_memory_test.py` to check Cuda compatability

### **Inference on New Audio**

```python
import torch
import numpy as np
from train import VesselCNN

# Load model
model = VesselCNN(n_classes=4)
checkpoint = torch.load('data/Interim/checkpoints/best_model.pth')
model.load_state_dict(checkpoint['model_state_dict'])
model.eval()

# Load normalization stats
with open('data/Interim/norm_stats.json') as f:
    stats = json.load(f)

# Process new audio
new_spectrogram = np.load('path/to/new_audio_spectrogram.npy')
normalized = (new_spectrogram - stats['mean']) / stats['std']
tensor = torch.from_numpy(normalized).unsqueeze(0).unsqueeze(0)  # (1, 1, H, W)

# Predict
with torch.no_grad():
    logits = model(tensor)
    probs = torch.softmax(logits, dim=1)
    predicted_class = torch.argmax(probs, dim=1).item()

class_names = ['Cargo', 'Passenger', 'Tanker', 'Tug']
print(f"Predicted: {class_names[predicted_class]}")
print(f"Confidence: {probs[0, predicted_class].item()*100:.1f}%")
```
